# Feature: A11Y-1 — Accessibility verification pass

Status: **in progress** — this specification was written before the remediation
code, per `docs/architecture/08-FEATURE-TEMPLATE.md`. Evidence is at the end and
is filled in as the work lands.

## Purpose

A11Y-1 answers one question honestly: **can someone who cannot use a mouse, or
who uses a screen reader, complete the flows EduReach exists for?** — check a
service, apply for it, practise CBT, and read the result — and does the
repository keep that true after this feature ships?

The audit framing is deliberate: *responsive testing is not accessibility
testing*. A layout that collapses to one column at 380px says nothing about
focus order, accessible names, or whether the exam clock can be perceived
without sight. This pass is therefore a **verification pass first and a
remediation pass second**: measure, fix what blocks people, and leave behind a
check that fails when the fix regresses.

Scope decisions (standing constraints): no frontend redesign, no new component
library, no replacement of the CBT engine, and no rewriting of the design
system. Remediation is limited to semantics, focus behaviour, and colour/contrast
corrections that a reviewer can read as a diff.

## User

* **Keyboard-only student** — tabs through the header, the service list and the
  apply wizard; cannot use a mouse.
* **Screen-reader student** — needs to hear what a control is, whether an exam
  clock is running out, and whether their submission failed.
* **Low-vision student** — needs a focus indicator they can see and text that
  meets contrast minimums.
* **Admin/content editor** — same requirements on the console forms and tables.
* **Maintainer/reviewer** — needs the posture to be machine-checked, not
  re-discovered by hand each quarter.

## User Flow

1. A keyboard user loads any page and presses <kbd>Tab</kbd>. The first stop is
   "Skip to main content"; activating it moves focus into `<main>` instead of
   through ~20 header/nav stops on every navigation.
2. The user opens a dialog (article preview, student activity, security
   settings, CBT submit confirmation, account sheet, question palette). Focus
   enters the dialog, <kbd>Tab</kbd> stays inside it, <kbd>Esc</kbd> closes it,
   and focus returns to the control that opened it.
3. In a CBT practice session the user hears the question, can move between
   answer options with the arrow keys, and is told when the clock crosses the
   five-minute and one-minute marks.
4. A form submission that fails announces the error; the field the error
   belongs to is marked invalid.
5. The maintainer runs `npm run a11y:audit` (or CI does) and gets a findings
   table; a new unlabelled input, an unlabelled dialog, a header cell without
   `scope`, a second `<main>`, or a removed skip link fails the build.

## Screens

All public routes, the student dashboard shell, and the admin console. The
highest-value screens are the ones the audit names: service catalogue and apply
wizard, CBT practice/results, news, school finder, and the auth screens.

## Routes

No new routes. Every existing route is in scope for verification; remediation is
concentrated where a finding was recorded.

## Components

New (shared primitives, deliberately small):

| Component | Responsibility |
|---|---|
| `src/components/a11y/SkipLink.tsx` | Renders the bypass-block link and targets `#main-content`. |
| `src/lib/useModalDialog.ts` | Focus entry, focus containment (<kbd>Tab</kbd>/<kbd>Shift+Tab</kbd>), <kbd>Esc</kbd> to close, focus restore to the opener. Used by every `role="dialog"` surface. |

Touched (attributes, focus behaviour, or colour only):

`HubLayout`, `AdminLayout`, `StudentDashboardV2`, `SecurityModal`,
`ScientificCalculator`, `AdminNewsPage`, `AdminUsersPage`, `CbtPracticePage`,
`AuthPageV2`, `ServiceApplyPage`, admin forms/tables, and the six pages that
currently render a nested `<main>`.

New stylesheet: `src/styles/a11y.css`, imported **last** in `src/main.tsx` so the
focus ring and skip link cannot be overridden by the eleven stylesheets that are
loaded around them.

## User Actions

* <kbd>Tab</kbd> / <kbd>Shift+Tab</kbd> — move focus; visible indicator on every
  focusable element.
* <kbd>Enter</kbd> on the skip link — jump to main content.
* <kbd>Esc</kbd> — close an open dialog or the calculator.
* <kbd>↑</kbd>/<kbd>↓</kbd>/<kbd>←</kbd>/<kbd>→</kbd> inside the CBT answer
  group — move and select an option.
* Existing CBT shortcuts (<kbd>A</kbd>–<kbd>D</kbd>, <kbd>N</kbd>, <kbd>P</kbd>,
  <kbd>F</kbd>, <kbd>S</kbd>) keep working unchanged.

## Button Logic

| Control | Keyboard behaviour | Why |
|---|---|---|
| Skip link | Hidden until focused; on activation moves focus to `#main-content` (`tabIndex={-1}`), not just scroll | 2.4.1 |
| Dialog close | Visible close button **and** <kbd>Esc</kbd>; both restore focus to the opener | 2.1.2, 2.4.3 |
| Modal backdrop | Click-to-close stays as a redundant mouse affordance; it is not the only way out | 2.1.1 — never make a pointer-only target the sole path |
| CBT option | `role="radio"` inside `role="radiogroup"`, roving `tabindex`, arrow keys, <kbd>Space</kbd>/<kbd>Enter</kbd> | 1.3.2, 2.1.1 |
| CBT clock | Announced at 5:00 and 1:00 through a polite live region | 2.2.1 |
| Icon-only button | Must carry `aria-label` (already true for all 0-findings cases; now enforced by the audit) | 4.1.2 |

## Data

No new persisted data. No user preference storage (no "reduced motion" toggle is
invented — the OS preference is honoured). Nothing about accessibility state is
sent to the server.

## Data Source

Three sources, all local and reproducible:

1. **Static AST scan** — `scripts/a11y-audit.ts` parses every `.tsx` under
   `pages/` and `src/` with the TypeScript compiler API. A regex scan is not
   enough here: `[^>]*>` truncates at the `>` inside `(event) => …`, which is
   exactly how the first hand-scan produced false "unlabelled input" hits on
   inputs that already had `aria-label`. The AST scan reads JSX attributes
   properly.
2. **Contrast computation** — colour literals in the CSS are compared against
   their plausible backgrounds for the WCAG 2.x contrast ratio (sRGB relative
   luminance). This is a *static* check on tokens, not a rendered-pixel check.
3. **axe-core in a real browser** — `tests/e2e/a11y.spec.ts` runs axe against
   the built app through Playwright on the project's own route list.

Baseline measured 2026-09-30 on `arena/01a0f3bd-edureach-hub` (AST scan; the
reproducible numbers come from `npm run a11y:audit` and are quoted in Evidence):

| Signal | Baseline |
|---|---|
| Bypass mechanism (skip link) | **absent** on every shell |
| `<main>` landmarks | 9 elements; **6 pages nest a second `<main>` inside `HubLayout`'s** |
| Focus indicator | global `:focus-visible` ring is `rgba(200,88,65,.24)` ≈ **1.3:1** on white |
| `outline: none/0` declarations in CSS | 23 (several in files loaded *after* `theme.css`) |
| `role="dialog"` / `aria-modal` / `<dialog>` | 8 / 5 / 0 — three dialogs are not modal, and five modal ones never take focus |
| `Esc` handling | 2 sites (`HubLayout` drawer, calculator) |
| `<th>` with `scope` | **0 of 25** |
| `aria-invalid` / `aria-describedby` | **0 occurrences in the repository** |
| `prefers-reduced-motion` coverage | 2 of 8 `@keyframes` |
| `<img>` without `alt` | 0 of 16 (three intentional `alt=""`, adjacent to a visible name/title) |
| Icon-only buttons without a name | 0 |
| Error announcements (`role="alert"`) | 28 sites — but **not** the sign-in banner or the service-apply failure |
| Route titles (`document.title`) | present for every route via `applyRouteSeo` (SEO-1) |

## Backend

None. Accessibility is a client-side contract; no server, RLS, or API change is
involved, and none of the ROLE-1 authorization rules are touched.

## Security

* No new data collection, no new network calls, no logging of user input beyond
  what already exists.
* The axe-core dependency is a devDependency; it is not shipped in the bundle.
* Nothing in this pass weakens an authorization decision: hiding a control from
  assistive technology is never used as a security boundary (ROLE-1 standing
  rule), and the remediation only *adds* semantics.

## States

| State | Accessibility requirement |
|---|---|
| Loading | Route/skeleton fallbacks already use `role="status"` + `aria-busy`; kept. |
| Empty | Empty states are real text in the reading order, not background images. |
| Error | Banner gets `role="alert"`; the offending field gets `aria-invalid` and `aria-describedby`. |
| Focus | Visible ring on every focusable element, including dark headers and the mobile bottom nav. |
| Reduced motion | Remaining keyframe animations are neutralised under `prefers-reduced-motion: reduce`. |

## Edge Cases

1. **Dialog inside a dialog** — the calculator opens inside the CBT practice
   screen; focus containment must not fight the parent. The hook is written so
   the inner-most dialog owns <kbd>Esc</kbd>.
2. **Skip link with a lazy route** — `#main-content` must exist after the chunk
   commits; the target element lives in the shell, which is mounted before the
   page chunk resolves.
3. **Mobile drawer vs. bottom nav** — both are `aria-current`-aware; the drawer
   already restores focus to its trigger and that behaviour is preserved.
4. **Exam clock thresholds crossed while the tab is hidden** — the announcement
   is emitted on state change, so a backgrounded tab announces once on return,
   not repeatedly.
5. **admin tables render zero rows** — `scope` must be present on the header
   cells regardless of row count.
6. **`alt=""` images next to a visible name** — deliberately decorative; the
   audit reports them as information, not as findings.

## Analytics

None. No event, no beacon, no third-party script is added by this feature.

## Notifications

No user-facing notification change. The CBT clock thresholds and the form error
banners reuse the existing `role="status"` / `role="alert"` patterns rather than
introducing a second announcement system (NTF-1 standing rule: no duplicate
notification paths).

## Testing

| Layer | Check | Runs |
|---|---|---|
| Unit (node:test) | `tests/a11y.test.ts` — the audit's rules asserted against the JSX tree: accessible names, dialog contract, `th scope`, no nested `<main>`, skip-link wiring, `aria-invalid` on validated fields | `npm test`, locally and in CI |
| Tooling | `npm run a11y:audit` — findings table for humans, non-zero exit when a rule fails | manual + CI gate via the test |
| Browser (Playwright + axe-core) | `tests/e2e/a11y.spec.ts` — axe on the public route list, desktop and mobile viewports, plus a keyboard test: skip link → focus lands in `<main>`; <kbd>Esc</kbd> closes a dialog and returns focus | `npm run test:e2e` (CI only — see limitations) |

No rule is disabled globally and no violation is downgraded to a warning; if a
rule cannot be satisfied yet, the exception is recorded in Evidence with the
reason and the follow-up, never silenced in code.

## Planned remediation (order of work)

1. **Critical/High, cheap, no design change** — skip link + `#main-content`
   targets; fix the six nested `<main>` landmarks; strengthen the focus ring;
   add `role="alert"` to the two unannounced error banners; `scope` on table
   headers.
2. **High, behavioural** — `useModalDialog` applied to the five modal surfaces;
   CBT answer-group roving focus + arrow keys; CBT clock threshold
   announcements.
3. **Medium** — accessible names for the remaining form controls, admin forms
   first; `aria-invalid`/`aria-describedby` on validated fields; `alt`/`scope`
   decisions recorded.
4. **Low** — reduced-motion coverage; remove pointer-only targets or give them a
   keyboard equivalent where one does not already exist.
5. **Verify** — `npm run a11y:audit`, `npm test`, `npm run ci` via the PR, and
   the axe E2E spec in CI. Fill Evidence; update the catalogue and README.

## Not applicable

* **RTL / localisation** — the product ships English only (`<html lang="en">`);
  no second locale exists to verify.
* **Captions / audio descriptions** — the product has no audio or video surface.
* **Screen-reader-specific behaviour for the CMS rich-text editor** — the editor
  is a content-authoring tool with a plain-text fallback field; it is reported as
  a known limitation rather than rebuilt in this pass.

## Known limitations (declared up front)

1. **No browser in this environment.** Playwright browsers cannot be downloaded
   here, so the axe pass executes in CI only. Until the CI run is green, the
   rendered-page claims remain *configured*, not *verified*.
2. **No assistive-technology testing.** NVDA/JAWS/VoiceOver and TalkBack passes
   were not performed. axe-core catches roughly the mechanically checkable
   subset; it cannot judge whether a flow is *understandable*.
3. **Contrast is verified for rendered pages by axe and statically for colour
   literals**; gradients, images-as-background, and disabled-state contrast are
   explicitly out of scope.
4. **Target size** is checked by inspection of the shared CSS (bottom nav 48px,
   primary buttons ≥38px) and by axe's `target-size` rule where it applies, not
   by an ergonomics study.
5. **Admin screens behind authentication are not scanned by axe** in this pass:
   the E2E suite deliberately runs without credentials. Admin remediation is
   covered by the static rules in `tests/a11y.test.ts` instead.
