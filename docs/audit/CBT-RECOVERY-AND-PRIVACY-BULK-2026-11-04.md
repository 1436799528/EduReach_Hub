## Remaining P0 work and proposed next engineering boundary

- **CBT concurrent and uncertain writes remain unsafe.** A full snapshot from a stale tab can overwrite a newer server draft. A timed-out request can commit later; same-tab serialization only orders acknowledged calls. The local compare/remove is best effort, and another edit can still overwrite a different stored copy. No automatic ordering between independent devices is proven. Restored local snapshots can themselves be stale and there is no complete compare/reconcile workflow. Invalid/corrupt local copies and account changes require further review.
- A versioned server-authoritative design must cover both draft endpoints, both submit paths and direct authenticated RPCs, owner assertion, existing legacy clients, immutable/idempotent retry identity, ambiguous acknowledgements, conflicts and safe local recovery. It must handle manual and timed submission with the existing deadline/grace rules without silently discarding answers or granting extra time. Inventory actual writers, privileges and migration ledger, test independent concurrent database sessions and realistic timeouts, and stage a compatible rollout/rollback before any authorization. A row lock alone is not enough.
- **Durable consent withdrawal remains a P0 blocker.** Browser storage that cannot be written or removed cannot by itself record a durable revocation for a later page; cross-tab messaging alone is not durable if a tab was absent or suspended. A global analytics kill switch would disable a working feature; per-document opt-in changes saved-consent behavior. Choose and review the product/privacy impact of a fail-closed design, test every actual transmission path and failures, and seek qualified legal review. The current error warning does not make earlier choices reliably revocable.
- Safe self-service deletion and administrator-reviewed exceptions, retention/backup policy, actual service reply/outcome handling, authoritative CI/preview on the reconciled branch, staging/UAT, live effective privileges and operational monitoring remain incomplete. Lifecycle approvals remain **0/16 formally approved gates** according to the reconciliation record. Historical broad seed/cleanup migrations must not be blindly applied to genuine records.
