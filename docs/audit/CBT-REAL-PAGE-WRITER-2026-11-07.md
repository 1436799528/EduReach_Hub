# CBT real page writer — local rehearsal

This record concerns the local-rehearsal v2 protocol only. Global v2 creation, public finalization and deployment remain disabled. Real Supabase Auth/PostgREST, hosted roles/RLS and production behavior are not verified.

## Integration and boundaries

The student page is `pages/CbtSessionPage.tsx`. Its legacy answer mutation remains `choose`/`clearAnswer` → `queueSave` → fenced `saveConfiguredCbtDraft`; legacy submission and abandonment remain fenced separately. The v2 branch validates the paper and journal and delegates the existing UI's choices to `useCbtPageWriter`, which orchestrates `IndexedDbAnswerJournal` and `CbtAnswerQueue`. It creates no second queue. Before acquisition, it stores an idempotent request identity per tab in the journal; a tab identifier in session storage and a lifetime Web Lock distinguish tabs, including duplicated tabs. These are routing and coordination aids, not authority. Only a validated server response supplies the lease ID and generation. An uncertain acquisition is retried with its durable request key.

Each answer is committed to IndexedDB before transmission, with a stable operation key and immutable lease. The page sends through the local-rehearsal Express answer route to the authenticated seven-argument `cbt_v2_answer_gateway`; it never writes CBT tables directly. The directly accessible authenticated PostgREST gateway is an independent boundary and derives identity in PostgreSQL. The executor-owned core and leased finalizer have no ordinary-client grants. Session takeover requires confirmation and a new durable request; a database-revoked lease cannot write. A cross-tab message may only stop sending, never confer ownership. A separate device without the message is rejected by the DB on its next request.

Unconfirmed work stays pending with its original operation and lease. Automatic retries are bounded at three after the initial attempt, with exponential delays; online and explicit retry may begin another bounded cycle. Editing pauses while an operation is pending or conflicted. When a lease is revoked, sending stops and pending work is preserved; where the authoritative state is reachable it is recorded for review. An operation from another or unknown lease is never automatically resent. The user may compare current server and local values, then explicitly keep the server answer or atomically link a new operation using the active lease and reviewed revision. A subsequent revision change forces review again. Disconnected work on other devices cannot be discovered by the server.

The page disables v2 submit and end actions, including the legacy submission/abandon paths. Neither local journal status nor a local seal is cross-device finalization authorization. The timer is a display/early stop only; the database controls the deadline. The application still exposes the local-only answer/state/session handlers only under the existing disposable-rehearsal guard.

## Verification and limits

Browser writer tests exercise the actual page and real IndexedDB/Web Locks but use synthetic Auth and a synthetic server. The separate HTTP compatibility rehearsal exercises real Express handlers and all 83 real migrations in disposable PostgreSQL, with synthetic Auth/JWT and a synthetic PostgREST adapter. The database session rehearsal exercises real PostgreSQL with synthetic SQL identities. None establishes real Supabase Auth, real PostgREST schema cache, hosted role graph or staging/production behavior. Real-stack prerequisites and safety gates remain in `docs/operations/CBT_REAL_SUPABASE_CHECKLIST.md`; do not target production.

The Vite configuration groups related administrator publishing routes into one lazy chunk and leaves the public critical path separately budgeted. This reduces total gzip size but makes those administrator routes share a larger first-load chunk; measure and review that tradeoff in staging. No performance budget was increased.

### Final integration repair (2026-11-07)

The earlier synthetic page tests did **not** establish that the real v2 paper could open. The actual `/api/cbt/attempts/:attemptId/paper` route called `get_cbt_attempt_paper`, which deliberately rejects v2. That prevented the actual page from reaching the writer against the real migrated database, even though mocked page tests passed.

The existing owner-scoped paper route now uses its already-guarded loopback rehearsal branch to read only the frozen IDs for a stored v2 attempt and only question text/options for the same exam. It rejects empty, malformed, duplicate, missing or ambiguous frozen IDs and restores their frozen order. It does not fetch correct options or explanations. Legacy still uses the fenced RPC; the RPC and production/Netlify/remote guards were not weakened. When the guard is off the legacy RPC continues to reject v2, rather than serving it as legacy.

`CBT_HTTP_BROWSER=1` on `scripts/rehearse-cbt-http-boundary.mjs` runs the actual built page, IndexedDB and browser through the real Express handlers, the local synthetic Auth/PostgREST compatibility layer and disposable PostgreSQL with all 83 migrations. This rehearsal passed: v2 opening, save/navigation/reload, pre-send failure and same-key retry, accepted-but-lost response and idempotent retry, two separate browser contexts, explicit takeover and stale in-flight refusal with original intent retained, explicit revision-conflict resolution, and legacy save/reload. It also verifies owner-scoped paper loading, v2 refusal when the local guard is off, legacy paper loading, no answer-key fields in the v2 paper, internal privilege separation and disabled HTTP finalization. The separate actual-page browser tests cover full Chromium restart and historical unassociated intent; their API services are synthetic. The private PostgreSQL session rehearsal separately checks serialized takeover/write races, roles, deadlines, and local rollback behavior with synthetic SQL identities.

This is stronger **local** integration evidence, not real Supabase Auth/PostgREST, hosted roles/RLS, staging, deployment or production evidence. The actual v2 page remains deliberately limited to local rehearsal until a separately reviewed and authorized staging path exists. The deletion blocker and public-finalization restriction remain in force.

Final checks after the repair: typecheck and **886/886** unit tests; browser suite **276 passed, 20 skipped**; mobile performance **1 passed**; performance audit **10/10**, JavaScript gzip **342,347 / 344,064 bytes**. Schema/RLS source audits and the 83-file checklist passed. The local build uses unconfigured Supabase fallback and is not a production deployment artifact; browser tests emitted missing-server-key warnings. No hosted project or deployment was changed.
