## Local database command and role assumptions

```
env -i PATH="$PATH" HOME="$HOME" node scripts/rehearse-cbt-protocol-fence.mjs /tmp/cbt-reconstruction-tools/node_modules/embedded-postgres/dist/index.js
```

The script uses a private Unix socket and disposable PostgreSQL, applies the real migrations and only then temporarily installs the non-migration guard candidate. Its synthetic non-superuser login may assume `authenticated`, `service_role` or `cbt_v2_client`; no application role inherits `cbt_v2_executor`. This tests SQL execution and constraints, not real Supabase Auth, hosted RLS behavior, hosted role membership, PostgREST or actual HTTP-to-PostgreSQL integration.

The guard's owner is the disposable migration owner. Before proposing it as a deployable migration, verify hosted permissions to create triggers on `auth.users`, ownership and row-security visibility, availability and effects on Supabase-managed Auth, concurrent transactions and operational recovery. Its refusal message is not a self-service deletion workflow. It deliberately supplies no retention period, exception policy, or completion claim.

## Explicit HTTP verification gap

No command in this report demonstrates a valid v2 answer or finalization through the real Express handler against migrated PostgreSQL. Existing `tests/authorization.test.ts` is an HTTP handler test backed by a synthetic Auth/PostgREST fixture, and the SQL rehearsal invokes RPCs directly. They are not interchangeable. The missing integration includes authenticated and rejected HTTP users, wrong ownership/protocol, direct-RPC denials, replay/conflict, finalization races and impersonation negatives under the actual chosen server execution principal.

## Local verification results

- Above disposable PostgreSQL rehearsal: passed. The real migrations were applied; the candidate blocked two raw deletes each for active legacy and v2 users, preserving attempts and the v2 ledger; a delete blocked by a concurrent uncommitted attempt insert then refused after its commit; no ordinary role had execute on the candidate trigger function. After the legacy attempt was explicitly abandoned, the proposed active-attempt guard allowed its Auth-row delete. The existing v2 fence still blocked deletion of a cancelled v2 attempt until its separate restricted attempt-deletion transition. This is not a hosted or complete deletion proof.
- `npm run typecheck`: passed. `npm test`: **875/875 passed**. `tests/authorization.test.ts` uses a synthetic Supabase backend; the new seal fault injection uses fake IndexedDB.
- `npm run build && npm run perf:audit`: passed. JavaScript gzip total **343,463 / 344,064 bytes**, level 6. The local preview build intentionally lacks hosted Supabase configuration.
