## Progress, tests and unresolved architecture dependency

- **Baseline/design:** the 137 matching files and unique programme were checked before changes. TypeScript passed. No application behavior, database migration, page writer, recovery hookup or submission was implemented. The v2 page remains blocked; the separate SQL candidate is still nondeployable.
- **Safe local test boundary added:** `scripts/cbt-disposable-safety.mjs` and `tests/cbt-disposable-isolation.test.ts` extend `scripts/rehearse-cbt-candidate-races.mjs`. It rejects ambient DB/credential/proxy/preload/production settings before importing the supplied module, creates a private Linux temporary directory, uses Unix sockets with TCP listening disabled, and verifies *every* connection's data directory, socket directory, `listen_addresses`, server address and database before migration/fixture writes. Its initial negative test reproduced the unsafe import ordering (2 passed / 1 failed); after the change **3/3 passed**. The embedded module and host OS are trusted, and Node preloads can execute before any script preflight; a clean environment was used. This protects only this rehearsal, **not** `scripts/rehearse-cbt-v2-http.mjs`, the application gate, or a real-page network test. Loopback alone still does not prove isolation.
- **Disposable PostgreSQL:** `env -i PATH="$PATH" HOME="$HOME" node scripts/rehearse-cbt-candidate-races.mjs /tmp/cbt-reconstruction-tools/node_modules/embedded-postgres/dist/index.js` passed after **79 synthetic migrations plus the nondeployable candidate**. It exercised same-key races, stale conflict, lost-response replay, finalization and post-lock answer/grace and expiry races. The candidate globally revokes legacy privileges inside that synthetic cluster, so this is not mixed-version or migration acceptance.
- **Role feasibility only:** `tests/cbt-fence-role-feasibility.test.ts` passed **1/1** against PGlite with synthetic roles/table/functions. It demonstrates that an invoker-context trigger can distinguish a narrow `SECURITY DEFINER` owner from direct/legacy writes when the authenticator session cannot assume that role. It does not validate any real migration, Supabase's actual roles or every privileged writer. A probe using `SET ROLE` from a superuser session could assume the narrow role; the test explicitly uses `SET SESSION AUTHORIZATION` for a non-superuser authenticator instead. This is an architectural property test, not an integrated protocol.
- **Actual blocker — creation and legacy entry:** replayed migration catalog inspection identified **15** functions referencing CBT tables, including authenticated `start_cbt_attempt`, `start_cbt_attempt_configured`, `save_cbt_attempt_draft`, both direct/configured submit, paper/expiry, abandon and delete; the old aliases also exist with different grants. These are security-definer functions owned by `postgres` in the local shim. The configured start locks by **user/exam/mode**, but the unique active-attempt index and its cancellation update are by **user/exam**. An old start can return a v2 attempt without any row mutation (so a row-write trigger alone cannot reject it), while another-mode start can cancel an existing attempt. Calling the existing creator to get a new v2 row can therefore cancel a concurrently created v1 attempt; checking for existing attempts before the call is not sufficient. The older `start_cbt_attempt` uses a different advisory key and also returns an existing row. A per-attempt trigger alone and the candidate's global revocations do not implement safe start/resume/legacy compatibility. A shared, concurrency-safe creation/planning contract and exact v1 parity across all these entries must be established and tested before claiming a deployable v2 migration; do not work around it by changing the rules, copying the global-revoke candidate, or silently converting records. This blocks integration and finalization.
- **Other unresolved dependencies:** the actual hosted role model, inherited memberships and privileged functions are not proven; the synthetic role test is insufficient. Strict cross-device freeze/drain and crash/reopen participant identity must be proved before finalization. No timeout can establish that an offline participant has no unsent intent.
- **Baseline/production build:** `npm run build` passed. Exact sum of emitted JS gzip level 6 **344,616 / 344,064 bytes**, **552 over**. `npm run perf:audit` **9/10**, failing all-chunks JS. No budget or correctness check was relaxed.
- **Unit/schema:** baseline `node --import tsx --test tests/cbt-*.test.ts` **122 passed** before new safety tests. `npm test` after isolation additions **860 passed / 2 failed / 0 skipped of 862** (the budget and missing candidate RPC schema assertions); the later role-feasibility test was run separately. Migration/schema/checklist suite **41 passed / 1 failed of 42**, missing `cbt_candidate_answer` and `cbt_candidate_finalize`. No dummy RPC was added.
- **Browser/performance:** `npm run test:e2e` on desktop/mobile Chromium **246 passed / 20 skipped**; these include actual guarded v1/v2 page tests and standalone/mocked harnesses, but no actual-page v2 writer, two-editable-tab, recovery or finalization proof. `npm run e2e:perf` **1 passed**. Local server logs included expected missing Supabase configuration for unrelated requests. Browser skips are not passes.
- **Hosted/CI:** no authoritative GitHub CI, staging/Auth/RLS or production verification, hosted migration or data change. `npm run ci` was not run as a complete chain; full unit and standalone perf/schema failures preclude a passing CI claim.
