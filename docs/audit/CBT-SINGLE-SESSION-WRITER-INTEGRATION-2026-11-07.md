## Browser-facing write boundaries

Legacy answer snapshots use `saveConfiguredCbtDraft` through the legacy route and fenced legacy DB RPC; legacy submit and abandon remain separate. V2 local rehearsal transport exposes an authenticated answer route and session endpoint; its database gateway is also directly reachable by an authenticated PostgREST client, so DB ownership, attempt protocol, current session and generation checks are the security boundary, not Express or browser flags. Restricted answer cores and leased finalization are not intended to be executable by ordinary client roles. The v2 finalization route stays closed, and a local journal seal is not a cross-device submission authorization. Actual hosted grants and Auth/PostgREST behavior remain unverified.

## Required next integration

Use the durable request key before every server acquisition and persist only matching validated server responses. A takeover must require explicit confirmation, preserve all previous operations and stop old-session sends on revocation. Use the original recorded lease when retrying; an unassociated or old-generation row must be reviewed instead of silently rebound. Validate paper and server state, recheck identity and response generations after asynchronous work, and serialize cross-tab review/replacement. Only an explicit local choice may create a new operation bound to the current lease, with a fresh revision and auditable replacement link; a changed server state must trigger another review. Show pending, acknowledged, revoked and conflict status and explain that disconnected work on other devices cannot be discovered. Keep finalization unavailable. Add real-page browser tests for first acquisition, restart, tabs, takeover/write races, network retries, replay, revocation, conflicts, and legacy behavior; then rerun all checks against the final build. Real Supabase and authorized staging verification remain separate.
